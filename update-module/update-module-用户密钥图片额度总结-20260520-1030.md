# 用户密钥图片额度修改总结

## 修改范围

- 后端用户密钥增加图片额度字段：`image_quota`、`image_quota_reserved`、`image_quota_available`。
- 旧用户密钥缺少额度字段时默认额度为 `0`，需要管理员充值后才能生图。
- 管理员创建用户密钥时可设置初始额度，并可通过充值接口增量增加额度。
- 普通用户可通过 `GET /api/auth/me` 查看自身密钥余额，登录响应也返回余额字段。
- 同步文生图 `/v1/images/generations` 和图生图 `/v1/images/edits` 接入预占额度、成功确认、失败退款。
- 异步图片任务 `/api/image-tasks/generations` 和 `/api/image-tasks/edits` 接入预占额度，并在任务记录中保存 `quota_reservation`、`quota_cost`、`quota_status`。
- 额度预占改为 `image_quota_reservations` 台账模型，确认和退款按 reservation id 幂等处理，避免重复扣费或重复退款。
- 图生图在读取上传文件或远程图片前先校验并预占额度；异步图生图会把同一笔预占直接交给任务服务持久化，避免读图成功后释放再重抢造成并发竞态。
- 异步任务在任务文件保存失败时会移除内存任务并退回预占额度，避免保存失败后额度长期卡住。
- 异步图生图拆分为准备任务和启动任务两阶段：准备阶段先保存带预占状态的任务，再读取图片；读取失败、请求取消、任务启动失败都会把任务标记失败并退款。
- 异步任务确认扣费或退款后，会清理任务记录中的活动 `quota_reservation`，仅保留 `quota_cost` 和 `quota_status` 用于展示和排查。
- 相同 `client_task_id` 并发提交时，只有真正创建准备任务的请求继续读取图片和启动任务，后续请求直接返回既有任务，避免重复读图或误伤已预占任务。
- 服务重启时，未完成异步任务会标记失败并退回预占额度。
- 系统设置增加文生图和图生图额度倍率，默认均为 `1`，支持小数，后端限制为大于 `0` 的倍率。
- 前端用户密钥管理页增加初始额度、余额展示、充值弹窗，并在新密钥展示区附带 OpenAI 兼容 curl 调用演示；画图页普通用户显示自身密钥余额。
- 复查后同步图片请求的临时预占增加 24 小时过期恢复标记；鉴权数据重新加载时会清理过期预占，避免确认和退款都因存储异常失败后长期卡住额度。
- 复查后恢复账号类型归一化和嵌套搜索兼容逻辑，避免 ProLite 等账号类型识别测试漂移。
- 复查后调整异步图片任务成功状态写入时机，减少 worker 在成功状态已可见后继续写任务文件造成的测试清理竞态。

## 接口变化

- `POST /api/auth/users`
  - 新增入参 `image_quota`，默认 `0`。
- `POST /api/auth/users/{key_id}/quota`
  - 新增接口，入参 `amount`，按增量充值用户密钥图片额度。
- `GET /api/auth/me`
  - 新增接口，返回当前密钥身份和余额字段。
- `GET /api/auth/users`
  - 用户密钥项新增余额字段。
- `POST /api/settings`
  - 支持保存 `image_quota.generation_multiplier` 和 `image_quota.edit_multiplier`。

## 扣费规则

- 管理员密钥不扣用户密钥额度。
- 普通用户密钥按 `图片张数 * 对应倍率` 预占额度。
- 旧用户密钥额度缺省为 `0`，由于倍率不能为 `0`，未充值密钥无法绕过额度限制。
- 成功返回图片数据后确认扣除。
- 上游失败、无图片数据、异常、异步任务失败时退回预占额度。
- 异步图生图在读取图片期间服务重启时，启动恢复会根据已保存任务退回预占额度。
- 额度不足返回 HTTP 429，错误信息为“图片额度不足，请联系管理员充值”。

## 残余风险

- 当前未在完整前端依赖环境中跑通 Next.js 构建。
- 同步流式接口在客户端断开时会按生成器关闭路径确认或退款；极端进程崩溃仍可能短期留下同步请求的已预占额度，新预占会在 24 小时过期恢复窗口后释放。
- 额度使用小数存储为 JSON number，已按 6 位小数规整；如未来要做财务级结算，建议迁移为整数微额度。

## 回滚建议

- 回滚本次涉及文件即可恢复旧行为。
- 若已产生带 `image_quota` 字段的 `auth_keys` 数据，旧代码会忽略额外字段，不影响密钥认证。
